# ФинРост (FinRost)

**Финансовый рост** — приложение для учёта инвестиций: депозитные счета, активы (акции, облигации, фонды, крипто), транзакции, срезы портфеля и аналитика.

## Возможности

- **Депозитные счета** — учёт счетов в разных валютах (RUB, USD, EUR, CNY), пополнения и списания.
- **Активы** — покупка, докупка, продажа акций, облигаций, фондов; автоматический пересчёт средней цены.
- **Транзакции** — журнал всех операций (покупки, продажи, купоны, дивиденды, пополнения, списания).
- **Срезы портфеля** — ежемесячные снимки стоимости по каждому счёту.
- **Анализ** — динамика портфеля, доходность, доходы, финансовый результат (Финрез) и эффективность (TWR / XIRR) с графиками.
- **Курсы валют** — автоматическое обновление с ЦБ РФ.
- **Импорт** — исторические срезы и доходы из CSV; заявки QUIK из Excel.
- **Реестр тикеров** — справочник тикеров с названиями.
- **Архивация** — автоматическое резервное копирование базы данных в ZIP при закрытии программы.

## Технологии

- Python 3.10+
- tkinter + ttkbootstrap (интерфейс)
- SQLite (база данных)
- matplotlib (графики)
- requests (курсы ЦБ РФ, цены Московской биржи)

## Установка

```bash
pip install -r requirements.txt
```

## Запуск

```bash
python main.py
```

При первом запуске создаётся база данных `investments.db` рядом с приложением. При обновлении версии схемы миграции применяются автоматически (см. `db_schema.py`).

## Импорт заявок QUIK

Исполненные заявки из терминала QUIK импортируются напрямую из XLSX, конвертировать в CSV не нужно.

### 1. Столбцы в таблице заявок QUIK

Перед экспортом настройте таблицу заявок (правая кнопка мыши по таблице → «Настройка таблицы…»). Для импорта нужны столбцы:

| Столбец | Назначение |
|---|---|
| **Номер** | ключ защиты от дублей — обязательно |
| **Операция** | Купля / Продажа — обязательно |
| **Код инструмента** | ISIN / тикер |
| **Инструмент** | название; по секции в скобках (напр. `[Т+: Облигации]`) угадывается тип инструмента |
| **Цена** | цена сделки |
| **Кол-во** | количество |
| **Объем** | сумма операции (для облигаций — с НКД); если нет — считается как Цена × Кол-во |
| **Валюта** | QUIK-код `SUR` распознаётся как RUB |
| **Состояние** | по умолчанию к импорту отмечаются только «Исполнена» |
| **Выставлена (время)** | сохраняется в комментарии транзакции |

Столбцы «Остаток» и «Код класса» импортером не используются — включать их не обязательно. Лишние столбцы не мешают: колонки распознаются по заголовкам.

### 2. Экспорт в Excel

Правая кнопка мыши по таблице заявок → «Вывод через DDE» (**Ctrl+L**).

В открывшемся окне:

1. **Рабочая книга** — выбрать существующий файл Excel или создать новый и указать его.
2. **Лист** — указать имя листа, например `Sheet1`.
3. Установить галочку **«Запускать приложение DDE сервера автоматически»** — без неё экспорт в файл не начнётся.
4. Внизу нажать **«Начать вывод»**.

![Окно экспорта из QUIK в Excel](PICT/Exporting%20from%20QUIK%20to%20Excel.png)

> **Важно:** импортер читает только первый лист книги (максимум — второй). Если вы правили файл в Excel и данные оказались на другом листе, переместите их на первый — иначе импорт завершится ошибкой «не найден лист данных». Видимое имя листа («Лист1», «Sheet1») роли не играет — важно его положение.

### 3. Импорт в ФинРост

Настройки → Хранилище → **Импорт заявок QUIK**:

1. Выберите брокера, нажмите «Выбрать файл…» и укажите сохранённый XLSX.
2. В окне предпросмотра отметьте заявки (по умолчанию отмечены исполненные), выберите счёт и дату сделки — в файле экспорта даты нет, ставится одна на все заявки.
3. Если среди заявок есть новые тикеры, подтвердите их тип (акция / облигация / ETF) — тип предугадывается по секции биржи, но его можно изменить или оставить незаданным (заполнится позже в реестре тикеров).
4. Нажмите «Импорт».

Заявки записываются в журнал транзакций (покупка/продажа). С включённой галочкой «Изменять активы и баланс счёта» (по умолчанию) импорт работает как обычные сделки в приложении: покупки создают/докупают позиции во вкладке «Активы», продажи списывают позицию с расчётом прибыли, баланс счёта изменяется (сумма записывается в валюте счёта). При нехватке средств баланс может уйти в минус — об этом будет предупреждение; продажа инструмента без позиции на счёте записывается только транзакцией. Со снятой галочкой заявки пишутся только в журнал. Уже импортированные заявки показываются серыми с пометкой и повторно не записываются — сверка по номеру заявки.

## Структура проекта

- `main.py` — точка входа, главное окно
- `version.py` — название и версия приложения
- `database.py` — слой данных (SQLite): запросы к таблицам
- `db_schema.py` — создание схемы БД и миграции (первый запуск / обновление версии)
- `app_config.py` — конфигурация (путь к БД, настройки архивации)
- `accounts_view.py` — вкладка депозитных счетов
- `assets_view.py` — вкладка активов
- `transactions_view.py` — вкладка транзакций
- `cuts_view.py` — вкладка срезов
- `analysis_view.py` — вкладка анализа
- `performance.py` — расчёт показателей доходности (TWR, XIRR) на чистом Python
- `settings_view.py` — настройки (валюты, импорт, база данных, архивация, тикеры)
- `quik_import.py` — импорт заявок QUIK из XLSX в транзакции
- `api_client.py` — внешние API (ЦБ РФ, Московская биржа)
- `snapshot_guard.py` — проверка актуальности данных и сохранение срезов
- `calendar_utils.py`, `table_utils.py` — вспомогательные утилиты
